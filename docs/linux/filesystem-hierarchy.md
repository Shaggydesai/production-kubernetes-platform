\# Linux Filesystem Hierarchy (FHS)



\## Overview



Unlike Windows, Linux does not use multiple drive letters such as `C:\\`, `D:\\`, or `E:\\`.



Everything in Linux starts from a single root directory:



```

/

```



Every file, directory, disk, device, and process is accessible somewhere under this root.



The Filesystem Hierarchy Standard (FHS) defines the purpose of each major directory, making Linux systems consistent across distributions.



\---

```
├── root

├── srv

├── sys

├── tmp

├── usr

└── var

```



\---



\# /



\## Purpose



The root of the entire Linux filesystem.



Every file and directory ultimately resides somewhere beneath `/`.



\### Example



```bash

ls /

```



\### Kubernetes Relevance



Everything Kubernetes uses is located somewhere under the root filesystem.



\---



\# /bin



\## Purpose



Contains essential user commands required for booting and basic system operation.



Examples include:



\- ls

\- cp

\- mv

\- cat

\- rm

\- mkdir

\- echo



\### Example



```bash

ls /bin

```



\### Note



On modern Ubuntu, `/bin` is a symbolic link to:



```

/usr/bin

```



\---



\# /sbin



\## Purpose



Contains essential system administration commands.



Examples include:



\- fsck

\- reboot

\- shutdown

\- ip



\### Example



```bash

ls /sbin

```



\### Note



Modern Ubuntu links `/sbin` to:



```

/usr/sbin

```



\---



\# /usr



\## Purpose



Stores most user-space applications, libraries, and documentation.



The name originally meant \*\*Unix System Resources\*\*, not "User."



Important subdirectories:



```

/usr/bin

/usr/lib

/usr/share

/usr/local

```



\### Example



```bash

which ls

```



Output:



```

/usr/bin/ls

```



\### Kubernetes Relevance



Most Kubernetes binaries are installed under `/usr/bin`.



\---



\# /etc



\## Purpose



Stores system-wide configuration files.



Nothing here is usually executable.



Examples:



```

/etc/passwd

/etc/group

/etc/hosts

/etc/fstab

/etc/ssh/

/etc/systemd/

```



\### Example



```bash

ls /etc

```



\### Kubernetes Relevance



Very important.



Examples:



```

/etc/kubernetes/

/etc/containerd/

/etc/cni/

```



Configuration for:



\- kubelet

\- kubeadm

\- containerd

\- networking

\- certificates



\---



\# /var



\## Purpose



Stores variable data.



Data here changes frequently.



Examples:



```

/var/log

/var/cache

/var/lib

/var/tmp

```



\### Kubernetes Relevance



One of the most important directories.



Examples:



```

/var/lib/kubelet

/var/lib/containerd

/var/lib/docker

/var/log/pods

```



Contains:



\- Pod data

\- Images

\- Container runtime data

\- Logs

\- Volumes



\---



\# /home



\## Purpose



Contains home directories for regular users.



Example:



```

/home/sagar

```



\### Example



```bash

pwd

```



Output



```

/home/sagar

```



\### Kubernetes Relevance



Mostly used for administrators and developers.



Not used directly by Kubernetes.



\---



\# /root



\## Purpose



Home directory of the root user.



Do not confuse this with `/`.



```

/

```



is the filesystem root.



```

/root

```



is simply root's home directory.



\### Example



```bash

sudo -i

cd /root

```



\---



\# /proc



\## Purpose



Virtual filesystem generated by the Linux kernel.



Files here do not exist on disk.



They are created dynamically.



Examples:



```

/proc/cpuinfo

/proc/meminfo

/proc/version

/proc/modules

```



\### Example



```bash

cat /proc/cpuinfo

```



\### Kubernetes Relevance



Kubernetes reads information from `/proc` to determine:



\- CPU

\- Memory

\- Process information



\---



\# /sys



\## Purpose



Virtual filesystem exposing kernel objects and hardware information.



Examples include:



\- CPU

\- Memory

\- Block devices

\- Network interfaces



\### Example



```bash

ls /sys

```



\### Kubernetes Relevance



Container runtimes and Kubernetes use `/sys` for resource and device information.



\---



\# /dev



\## Purpose



Represents devices as files.



Examples:



```

/dev/null

/dev/random

/dev/tty

/dev/nvme0n1

/dev/sda

```



\### Example



```bash

ls /dev

```



\### Kubernetes Relevance



Volumes and block devices are exposed through `/dev`.



\---



\# /boot



\## Purpose



Contains everything required to boot Linux.



Includes:



\- Linux kernel

\- initramfs

\- GRUB bootloader files



\### Example



```bash

ls /boot

```



\---



\# /run



\## Purpose



Stores runtime information.



Contents disappear after reboot.



Examples:



\- PID files

\- sockets

\- runtime state



\### Kubernetes Relevance



Many Linux services create runtime files here.



\---



\# /tmp



\## Purpose



Stores temporary files.



Applications may delete files from this directory at any time.



Never store important data here.



\### Example



```bash

touch /tmp/testfile

```



\---



\# /opt



\## Purpose



Optional third-party software.



Common examples:



\- Google Chrome

\- Oracle products

\- Custom enterprise software



\---



\# /mnt



\## Purpose



Temporary mount point for manually mounted filesystems.



Example:



```bash

sudo mount /dev/sdb1 /mnt

```



\---



\# /media



\## Purpose



Automatic mount location for removable media.



Examples:



\- USB drives

\- DVDs

\- External hard disks

\# Interview Questions



\## What is the root directory?



The root directory (`/`) is the top-level directory of the Linux filesystem. Every file and directory exists beneath it.



\---



\## What is stored in `/etc`?



System-wide configuration files.



\---



\## What is stored in `/var`?



Variable data such as logs, caches, databases, container images, and application state.



\---



\## What is `/proc`?



A virtual filesystem created by the Linux kernel that provides process and system information.



\---



\## What is the difference between `/` and `/root`?



`/` is the root of the filesystem.



`/root` is the home directory of the root user.



\---



\## Why is `/var/lib/kubelet` important?



It stores kubelet state, running Pod data, mounted volumes, Secrets, ConfigMaps, and other Kubernetes runtime information.



\---



\# Key Takeaways



\- Linux uses a single hierarchical filesystem rooted at `/`.

\- `/etc` contains configuration files.

\- `/var` stores variable and application data.

\- `/usr` contains applications and libraries.

\- `/proc` and `/sys` are virtual filesystems created by the kernel.

\- `/dev` exposes hardware devices as files.

\- Kubernetes relies heavily on `/etc` and `/var/lib`.
