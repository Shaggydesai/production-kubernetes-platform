\# Linux Kernel



\## What is the Linux Kernel?



The Linux kernel is the core component of the Linux operating system. It acts as the bridge between user-space applications and the computer's hardware.



Applications do not communicate directly with the CPU, memory, disks, or network devices. Instead, they make system calls to the Linux kernel, which performs the requested operations securely and efficiently.



\---



\## Responsibilities of the Linux Kernel



The kernel is responsible for:



\- Process management

\- CPU scheduling

\- Memory management

\- Filesystem management

\- Device drivers

\- Networking

\- Security

\- System calls

\## Interview Questions



\### What is the Linux kernel?



The Linux kernel is the core component of the operating system. It manages hardware resources, processes, memory, filesystems, networking, and exposes system calls to user-space applications.



\---



\### What is `/proc`?



`/proc` is a virtual filesystem created by the Linux kernel. It provides real-time information about processes and the running system and does not store data on disk.



\---



\### Does every Docker container have its own kernel?



No.



Containers share the host Linux kernel while maintaining isolated user spaces through namespaces and cgroups.

# Lesson 2 – System Calls

## What is a System Call?

A system call is the mechanism by which a user-space application requests a service from the Linux kernel.

Applications cannot access hardware directly. Instead, they use system calls to perform operations such as reading files, creating processes, allocating memory, or communicating over the network.

## Examples

- open()
- read()
- write()
- fork()
- execve()
- socket()
- mmap()

## User Space vs Kernel Space

User-space applications execute with limited privileges.

The Linux kernel executes in kernel space and has direct access to hardware resources.

All hardware operations are performed by the kernel on behalf of user-space applications.

## Kubernetes Connection

Containers share the host Linux kernel.

When Kubernetes creates a Pod, the container runtime uses Linux system calls to create namespaces, configure cgroups, mount filesystems, and start processes.

# Lesson 2 - User Space and System Calls

## User Space

User Space is where applications execute.

Examples:

- bash
- kubectl
- vim
- nginx
- containerd

Applications in User Space cannot directly access hardware.

---

## Kernel Space

Kernel Space contains the Linux kernel.

It manages:

- CPU scheduling
- Memory
- Networking
- Device drivers
- Filesystems

---

## System Calls

Applications communicate with the kernel using system calls.

Examples:

- open()
- read()
- write()
- execve()
- fork()
- socket()

---

## ELF

Linux executables use the ELF (Executable and Linkable Format) binary format.

Example:

```bash
file /usr/bin/ls
```

---

## Shared Libraries

Applications share common libraries such as:

- libc.so
- libselinux.so

These libraries reduce memory usage and simplify software maintenance.
