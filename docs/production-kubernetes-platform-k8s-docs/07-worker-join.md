# 07 --- Worker Node Join

## Worker inventory

``` text
k8s-worker01  192.168.75.137
k8s-worker02  192.168.75.138
```

Both workers use:

``` text
Ubuntu 24.04.4 LTS
Kubernetes v1.36.3
containerd 2.2.1
```

## Preparation

Each worker was prepared independently:

``` bash
hostnamectl --static
cat /etc/machine-id
ip -br addr
ip route
systemctl is-active containerd
```

Each worker had a unique hostname and machine ID.

## Join

Use the `kubeadm join` command generated by the control-plane
initialization.

The command has this general structure:

``` bash
sudo kubeadm join 192.168.75.136:6443   --token <token>   --discovery-token-ca-cert-hash sha256:<hash>
```

Do not store the real token in Git documentation.

If the token expires, generate a new join command on the control plane:

``` bash
kubeadm token create --print-join-command
```

## Verify workers

On `k8s-cp01`:

``` bash
kubectl get nodes -o wide
```

Final state:

``` text
k8s-cp01       Ready   control-plane   192.168.75.136
k8s-worker01   Ready   <none>          192.168.75.137
k8s-worker02   Ready   <none>          192.168.75.138
```

## Verify kube-proxy and Flannel

``` bash
kubectl get pods -n kube-system -o wide
kubectl get pods -n kube-flannel -o wide
```

Each node should have its kube-proxy and Flannel DaemonSet Pod running.
