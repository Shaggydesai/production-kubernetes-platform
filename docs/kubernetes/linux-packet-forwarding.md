\# Linux Packet Forwarding



\## Why Linux Networking Matters to Kubernetes



Kubernetes networking relies heavily on Linux networking primitives.



A simplified packet path is:



```text

Packet

&#x20; ↓

Network interface

&#x20; ↓

Linux kernel

&#x20; ↓

Routing decision

&#x20; ↓

Netfilter

&#x20; ↓

Forward / NAT

&#x20; ↓

Output interface

```



\## IP Forwarding



Linux can forward IPv4 packets between interfaces when:



```text

net.ipv4.ip\_forward = 1

```



Inspect with:



```bash

sysctl net.ipv4.ip\_forward

cat /proc/sys/net/ipv4/ip\_forward

```



IPv6 forwarding can be inspected with:



```bash

sysctl net.ipv6.conf.all.forwarding

```



\## Why Kubernetes Needs Forwarding



A Kubernetes node can route traffic between Pods, nodes and external networks.



Conceptually:



```text

Pod

&#x20;↓

Kubernetes node

&#x20;↓

another network interface

&#x20;↓

destination

```



The Linux kernel must be able to forward traffic between interfaces.



\## Routing



Inspect routes:



```bash

ip route

```



Ask Linux how it would route to a specific destination:



```bash

ip route get <destination>

```



Example:



```bash

ip route get 10.244.2.10

```



Linux uses longest-prefix matching when selecting routes.



\## Next Hop



A route can specify a next hop.



Example:



```text

10.244.2.0/24 via 192.168.10.102 dev eth0

```



Meaning:



```text

Destination network:

10.244.2.0/24



Next hop:

192.168.10.102



Interface:

eth0

```



\## ARP and Neighbours



IPv4 networking on Ethernet requires mapping IP addresses to MAC addresses.



Inspect neighbour information:



```bash

ip neigh

```



Example:



```text

192.168.10.102 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE

```



\## Layer 2 vs Layer 3



Layer 2:



```text

Ethernet

MAC

ARP

```



Layer 3:



```text

IP

routing

```



The Ethernet destination MAC and IP destination address are not necessarily the same.



\## Netfilter



Netfilter is the Linux kernel packet-processing framework.



It supports functionality such as:



\- filtering

\- NAT

\- connection tracking



User-space tools can configure packet processing through interfaces such as:



```text

iptables

nftables

```



\## iptables and nftables



Do not confuse:



```text

Netfilter

```



with:



```text

iptables

```



Netfilter is the kernel framework.



iptables and nftables are user-space interfaces/tools used to configure packet processing.



\## INPUT



Traffic destined for the Linux host itself follows the local-delivery path.



Conceptually:



```text

packet

&#x20;↓

INPUT

&#x20;↓

local process

```



\## FORWARD



Traffic routed through the Linux host uses the forwarding path.



Conceptually:



```text

packet

&#x20;↓

FORWARD

&#x20;↓

output interface

```



This is important for Kubernetes node traffic.



\## OUTPUT



Traffic generated by a process on the Linux host follows the output path.



Conceptually:



```text

local process

&#x20;↓

OUTPUT

&#x20;↓

network interface

```



\## IP Forwarding vs Firewall



These are different concepts.



IP forwarding answers:



```text

Can Linux route packets between interfaces?

```



Firewall rules answer:



```text

Is this particular packet allowed?

```



A node can have:



```text

net.ipv4.ip\_forward = 1

```



while firewall rules still block forwarding.



\## Connection Tracking



Connection tracking maintains state about network flows.



It is important for:



\- NAT

\- firewalling

\- Kubernetes Service traffic



Conceptually:



```text

Client → Server

Server → Client

```



can be tracked as one connection.



\## SNAT



Source Network Address Translation changes the source address.



Example:



```text

Before:



10.244.1.10 → 8.8.8.8



After:



192.168.10.101 → 8.8.8.8

```



This can be used when Pod traffic leaves the cluster.



\## DNAT



Destination Network Address Translation changes the destination address.



Simplified Service example:



```text

Before:



10.96.20.50:80



After:



10.244.2.10:8080

```



\## Kubernetes Networking



A simplified Kubernetes networking stack is:



```text

Pod

&#x20;↓

Network Namespace

&#x20;↓

veth

Linux Kernel

&#x20;└── conntrack

&#x20;↓

CNI / node networking

&#x20;↓

Destination

```



\## Troubleshooting Commands



Inspect interfaces:



```bash

ip addr

ip link

```



Inspect routes:



```bash

ip route

```



Inspect a specific route:



```bash

ip route get <destination>

```



Inspect neighbour state:



```bash

ip neigh

```



Inspect nftables:



```bash

sudo nft list ruleset

```



Inspect iptables where applicable:



```bash

sudo iptables -L -n -v

```



Inspect connection tracking:



```bash

sudo conntrack -L

```



Capture packets:



```bash

sudo tcpdump -i <interface>

```



\## Kubernetes Troubleshooting Principle



When a packet fails, identify the exact layer:



```text

Pod namespace

&#x20;↓

veth

&#x20;↓

routing

&#x20;↓

forwarding

&#x20;↓

Netfilter

&#x20;↓

NAT

&#x20;↓

node network

&#x20;↓

destination

```



Do not describe the problem simply as:



```text

"Kubernetes networking is broken."

```



Identify which Linux networking layer is failing.
